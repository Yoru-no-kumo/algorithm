# 引数渡し意味論 (Parameter Passing Semantics)

## 1. 引数渡し意味論とは?

プログラミング言語において、**関数が引数を受け取る際に、スタック・ヒープ・参照・値をどのような規則で扱うか**を定義する概念です。
即ち、言語が**「関数呼び出し時にどのようにデータを受け渡すか」**を説明する意味論モデルであります。

代表的な引数渡し方式:

- call by value  
- call by reference  
- call by sharing  
- (その他: call by name, call by need 等)

ここでは、話題にした主要3方式について整理します。

---
---

## 2. call by value (値渡し)

スタックに保存された「値」を、そのままコピーして関数のパラメータ変数（スタック領域）に渡す方式

- 値は数値・ブール等のプリミティブ型であれば → **実際の値そのものはコピー**される
- 値がオブジェクトであれば → オブジェクトの **参照（アドレス値）**がコピーされる  
  （つまり、*参照型変数はアドレス値自体を「値」としてコピー*される）

### 値渡しの特徴

- 同じヒープ帯ジェクトを参照し得るため、**オブジェクト内部の変更は元の値にも反映**される
- ただし関数内部でパラメータを**再代入**しても、元の変数には影響しない
    （スタック上の変数は互いに独立であるため）

### 値渡しを使用する言語

- C（ポインタを使っても、引数渡し自体は「値渡し」）
- Java（参照型も結局は「参照値の値渡し」）
- Python, JavaScript, Rubyも内部的には値渡し構造を用いる

---

## 3. call by reference (参照渡し)

関数のパラメータが、呼び出し元のスタック半数そのものを直接指す方式

- 関数内部のパラメータ変数と呼び出し元の変数が**同一スタックスロット**を共有する
- よって:
  - オブジェクト内部の変更 → 反映される
  - パラメータを再代入しても → 元の変数も同様に書き換わる

### 参照渡しの特徴

- 非常に強力だが、予測が難しく安全性が下がるため、現代の言語ではデフォルト動作としてはあまり使われない

### 参照渡しを使用する言語

- C++ (`T&`)
- C# (`ref`, `out`)
- Pascal (伝統的)

---
---

## 4. call by sharing (共有渡し)

参照（アドレス値）の「コピー」を渡すが、ヒープ尾辺ジェクトは共有されるモデルです

つまり

- 関数呼び出し時、スタック変数に保存された**参照値のみをコピー**  
- コピーされた参照値は同じヒープオブジェクトを指す
- したがって、内部変更は共有される

### 共有渡しの特徴

- オブジェクト**内部変更** → 元の値にも影響
- パラメータ**再代入** → 元の値には影響しない
- call by referenceと異なり**スタック変数そのものは共有しない**

### 共有渡しを使用する言語

- Python  
- JavaScript  
- Ruby  
- Java

## 5. 関係分析

参照型データに限定した場合

| モデル | 実際の挙動 | 参考 |
| ------ | ----------- | ------ |
| **call by value** | 参照値コピー → ヒープ共有 → 再代入は独立 | call-by-sharingと同等の効果 |
| **call by sharing** | 参照値コピー + ヒープ共有 | 表現が違うだけ |
| **call by reference** | スタック変数そのもの共有 | 再代入まで反映される |

| モデル | ヒープオブジェクト共有 | 内部変更の反映 | 再代入の反映 |
| ----------- | :------: | :------: | :------: |
| **call by value** | 〇 | 〇 | × |
| **call by reference** | 〇 | 〇 | 〇 |
| **call by sharing** | 〇 | 〇 | × |

つまり

- 参照型データについては **call by value = call by sharing**
- call by referenceは全く別のモデル
  (スタック変数を共有するかどうかが本質的な違い)

## 6. まとめ

- **引数渡し意味論**は関数呼び出し時に引数をどの規則で渡すのかを定義したモデル。
- **call by value**: 値（または、参照値）をコピーする。
  → 参照型にはヒープ共有 / 再代入は独立
- **call by reference**: スタック減数をを共有する。  
  → あらゆる変更が呼び出し元に反映
- **call by sharing**: 参照値のみコピーし、オブジェクトは共有する。
  → 参照型のcall-by-valueと実質的に同じ挙動
- 結論として、**産所型データ**に関しては  
  → *call-by-value（参照値） = call-by-sharing*
